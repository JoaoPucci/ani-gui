# Title resolution and the cross-API bridge

`ani-gui` reads from four catalogues that don't share an id space:

- **Kitsu** (REST/JSON:API) — discovery surface (search, trending fallback, top rated, recently released, detail pages, episode metadata).
- **AniList** (GraphQL) — recency-weighted "Trending Now" row, banner backfill when Kitsu's banner is null, and episode stills Kitsu lacks.
- **hianime** — the streaming catalogue the backend resolves playback against. anidb.app was the first until it was retired in October 2026; the history rows, numbering stamps and mappings it left are still read (see [What anidb.app left behind](./architecture.md#what-anidbapp-left-behind)).
- **aniskip** (REST) — community OP / ED skip-time intervals, keyed by MyAnimeList id.

Every interaction other than discovery has to find the same show in two or more of these. None of them carry the others' ids, and any given anime may appear in some but not others (aniskip in particular is sparse). This document describes how the backend bridges them and what the cache stores in the process.

## The four bridges

```
                       ┌──────────────────────────────────────────┐
                       │                                          │
                       │             Discovery surface            │
                       │                                          │
                       │   ┌──────────────┐    ┌──────────────┐   │
                       │   │   AniList    │    │    Kitsu     │   │
                       │   │  (trending)  │    │ (everything  │   │
                       │   │              │    │   else)      │   │
                       │   └──────┬───────┘    └──────┬───────┘   │
                       │          │                   │           │
                       │     mal id only         kitsu id (canonical
                       │          │              for the renderer)
                       └──────────┼───────────────────┼───────────┘
                                  │                   │
                  ┌───────────────┴───────────────────┘
                  │       Kitsu mappings endpoint
                  │       (kitsu id ↔ mal / anilist id)
                  ▼
       ┌──────────────────┐                ┌──────────────────────┐
       │     aniskip      │                │    stream provider   │
       │   (mal_id, ep)   │                │  (canonical title +  │
       │  → skip times    │                │   alt titles → hits  │
       │                  │                │   → probe episode    │
       │                  │                │   lists → pick)      │
       └──────────────────┘                └──────────────────────┘
```

Four distinct lookups, each with its own gotchas:

1. **Kitsu → provider title match** — the native walk searches the provider's catalogue: hianime's search page. Kitsu canonical titles (often the licensed English form) and the provider's index don't always agree, so the bridge tries the canonical first and falls back to romanized Japanese, native script, and known synonyms before giving up.
2. **Candidate disambiguation** — multiple search hits can match the same query string ("Gintama" returns the series and its movies in the provider's own ranking). The search page carries titles, a romanized name and a format badge, and no count, so the picker probes each considered hit's episode list — bounded to the first few hits whose titles could be the entry (with a count, the first few hits that cannot be picked are probed besides, as evidence), since real queries put the right show near the top and every probe is an upstream request — and Kitsu's authoritative `episode_count` picks the candidate whose count is closest.
3. **Kitsu ↔ MAL / AniList** — neither Kitsu's id nor the provider's slug matches MAL's or AniList's. Kitsu publishes a mappings endpoint that exposes the third-party ids it knows about; the backend fetches `kitsu/anime/:id?include=mappings` and walks the included documents for the MyAnimeList and AniList rows.
4. **MAL / AniList → aniskip / AniList** — once the ids are in hand, aniskip (MAL id only) and AniList's `Media(idMal:)` query are direct lookups. The banner and episode-thumbnail backfills fall back to AniList's `Media(id:)` when Kitsu carries the AniList mapping but no MAL one, which is common for fresh seasonal shows, and retry by that id once when AniList has no media for the MAL id.

## Title resolution: Kitsu → the provider

When the user clicks an episode, the backend builds a list of search terms from the Kitsu metadata in priority order and feeds them to the provider's search in turn:

1. Canonical title.
2. `titles.en_jp` (romanized Japanese).
3. `titles.ja_jp` (native script).
4. `titles.en` / `titles.en_us` (English alternates).

Empty / whitespace-only titles are skipped and exact-string duplicates are deduped, so the backend never makes a redundant provider query. A pool whose pick is rejected keeps the walk going — the next alias may carry the real show — while an upstream refusal (the provider's protection page) stops it: a block on one query blocks them all, and each further request deepens the hole.

## Disambiguation by episode count

The picker probes at most the first few browse hits the entry's titles admit via the episodes endpoint — with a count, plus the first few that cannot be picked, as evidence (see the decision tables below) — and scores each by the distance between its episode count and Kitsu's authoritative `episode_count`. The best distance wins, rejected outright when it exceeds the tolerance (`max(3, expected / 10)` — long-running shows get proportional slack, short shows a hard floor); ties prefer an exact title match on the search term, compared as written (case and spacing aside, catalogue tags wherever they stand). Copies of the winner under a version tag — hianime's "(Uncensored)" listings beside their plain re-uploads — are not chosen between: they are reported as versions of the one pick (see [Versions of one pick](#versions-of-one-pick)). The same picker is used by:

- **The play path** — so clicking "play" lands on the right show even when the provider ranks a movie or side story first.
- **The availability probe** — so the home / detail page's "is this in the catalogue?" gate matches what the play path would do.
- **The download path** — so a download started from the player picks the same show the player was streaming.

One Kitsu entry can be several shows on the provider. Steel Ball Run is twelve episodes on Kitsu, while hianime lists its March premiere as a one-episode show of its own and the weekly run as "… 2nd Stage", numbered from 1. The picker recognises the parts among the candidates it already probed — a bare title and the same title followed by a short part marker ("2nd Stage", "Part 3", "Season 2", "II"), every part's own premiere year equal to Kitsu's — and stitches them when together they explain the expected count better than any single candidate, either within the tolerance or short of it as an airing entry is. Where a single candidate already sits within the tolerance, the count cannot tell a finished split (1 + 11 against 12, the later part one off) from a cour and its same-year sequel (12 + 1 against 13, the bare title one off), so the near miss decides: the parts are stitched over it when it is one of the later parts, never when it is the bare title — a bare title that fits alone is the entry. The entry may itself be a later part: Kitsu keeps "X Season 2" as its own entry, and asked for it, the provider's same-year "X" is the season before. Any candidate that a title the entry goes by — its canonical title or any alias — names a later part of is dropped from the pool before probing, so it neither heads a chain (a finished 12-episode "X" beside a "X Season 2" five episodes into an announced 24 would otherwise stitch, 12 + 5 short of 24 like an airing split, and play Season 2's first twelve episodes from the first season), nor wins alone when its count happens to fit, nor stands in when the provider has not listed the later part yet. Steel Ball Run's Kitsu titles name no part, so its pool keeps both parts. The reverse has no title to go on: asked for a bare "X" that has finished but that the provider lists short, beside a same-year "X Season 2" that Kitsu keeps as its own entry, the two can still stitch when together they fit the count better than "X" alone, since nothing in the titles or counts tells that from a real split. Beyond that check the parts' titles are not compared with the one searched, so a provider that spells the parts differently from the title searched (an English title against Kitsu's romaji, say) stitches the same way, and an airing split stays stitched the week its later part comes within the tolerance. A bare title whose own listing is numbered as a continuation is never stitched: played alone, its key already carries that offset and its rows from before the own-number marker speak those numbers. Stitching makes one listing in the entry's numbering: each part normalised to its own numbers and numbered on from where the part before it ends, every row keeping the episode id it streams from, and every row taking its position across the parts as its slot, with its episode identity in the tag where the two differ — as a single listing's rows do. The first part's id is the show's identity, the key history and every cache file the plays under, so Kitsu's episode 2 of Steel Ball Run streams the 2nd Stage's episode 1 and records as episode 2 under the first part's key. A sibling that lists nothing yet, one from another year, a gap in the part numbers or a candidate whose probe failed leaves the pick as it was; so does a single candidate the rules above leave standing, which keeps a provider entry spanning several Kitsu entries on its continuation offset (below).

Before anything is probed, a card's format badge disproves candidates whose format cannot be the entry's: a movie is not a series, and a special, an OVA and a movie are not each other — for single-video entries of one title and year the badge is the only thing that separates them. TV and ONA are the one pair that does not disprove: a series a streaming service premiered is a TV series to one catalogue and a web release to the other (Stone Ocean is TV on Kitsu and ONA on hianime), and the count and year separate the two where they differ.

A hit its own entry page files under the genre Hentai is never a pick where that page is read: the app reads Kitsu anonymously, and Kitsu serves no adult entry that way, so no entry the app shows is one. The genre is read from the entry page the year filter already reads, so it reaches exactly the hits whose page that filter reads — every considered hit of an entry with a year, with a count or without, one video long or more — and the hit is dropped there as a hit from another year is: a pool holding nothing else the entry could be is the clean miss a pool of other years' shows is, since the page says positively that the listing is not the entry's. An entry with no year reads no entry page, and nothing here reaches its hits; the count-alone rule below, which takes only a hit the entry names, is what refuses the hentai OVAs Ohanashi de Te Koi and Tsubu★Doll were played as, and only a hentai listed under one of such an entry's own names could still be picked. The genre is read and never the search card's "18+" badge, which hianime also puts on shows that are no hentai (Ranma ½, Sword Art Online: Ordinal Scale, a Lupin III, Queen's Blade).

A single video's count is no identity. For an entry one episode long — a movie, a special, a one-episode show — every single video a search answers with sits at distance zero, a franchise's other films and specials and a crossover carrying the franchise's name among other shows' alike, and a hit whose entry page names no year is disproved by nothing. So for such an entry a probed candidate is picked only when it is the title searched, the entry names it (one of the entry's titles carries its name, reads as it does, carries the same words past that name and is written with the same primes and no conflicting release year — see the reader below), or its own year is the entry's; any other is scored out as a refused candidate is, and a pool rejected after that is the refusal by title the availability cache never persists, not a clean miss. Kitsu's Dragon Ball Z: The Real 4-D, a 2016 special hianime does not list, is refused rather than played as One Piece 4D, the 2015 one-episode special its Japanese title's search answers with — a year off, which the year filter tolerates as a December premiere; a film the provider lists under one of the entry's aliases, or from the entry's year, is picked as before. The refusal answers as the one by title because the count did accept the candidate: the rule overrides a fit on how the candidate is named. A candidate that dies before its listing is heard is not read by this rule — its death leaves the pool unheard and is weighed by its rank like any other.

A count with no year is no identity either. For an entry Kitsu counts but does not date — fourteen of its to-be-announced catalogue on 2026-10-15 — the count was all that scored a hit, and a count fits many shows: a title the provider does not list is answered with a page of other shows, and among thirty of them one within the tolerance is the rule rather than the exception. Seven of the fourteen were played as another show — a two-episode hentai OVA for the five-episode Tsubu★Doll, Girlfriend, Girlfriend for Mo Du Zhe — while the two the provider does list are both listed under a name one of the entry's titles carries. So for such an entry a probed candidate is picked only when it is the title searched or the entry names it, as a single video is; any other is scored out as a refused candidate is, and a pool rejected after scoring out a hit the count accepted is the refusal by title the availability cache never persists, not a clean miss. A dated entry is read by the rule below instead, which also lets the provider's own names for the show vouch. An entry one video long is read by the single-video rule above, the same reading. The availability probe answers such a refusal as it answers every verdict it cannot reach — a normal answer that says `unsettled`, persists nothing and is no error — and says why: `refused` when every pool the walk met was refused on how its hits are named, by this rule or any other that reads a hit's name (the title rule, the single-video rule, the dated-name rule below); `unanswered` for a dead listing or a mode nobody answered for — a dead listing anywhere beside a refusal included (one the title rule admits that the rule reading its name would have let stand — a name for a dated entry with a count; the title searched, a matched year or the entry's name for one a single video long or counted and undated — answering not-found in the refused pool, another alias's or another provider's), since it may have been the entry's; `past_affinity` and `superseded` for an absence the cache's own rows outrank — a refusal past a remembered provider that has not denied the show, or one a play overtook while the probe was out, among them. The renderer reads `refused` as the show not being in the catalogue — the detail page's notice in place of Play, the play page's episode tiles disabled as for a show the provider does not carry, the cap gate's unavailable, the search filter dropping a finished show's card (a show of every other status keeps it — airing, upcoming, to be announced, unreleased or of unknown status — as any show the provider does not list yet does) — since a Play there can only fail, and every other reason as the unknown it is. The refusal is still not persisted, but not persisting it no longer keeps a wrong one from hiding a show: the rules are deterministic, and every look reaches the same refusal. A show the provider lists under a name the rules do not take is a picker defect, fixed as every mispick is, with a recorded fixture.

A year and a count are no identity either. For a dated entry with a count above one, a hit whose page named the entry's year — or merely a year the filter tolerates, one off as a December premiere, or none — and whose count fit was picked on those alone, and a search for a title the provider does not list answers with a page of other shows among which one from the same year and of the right length is common: HenSemi (2010, two episodes) was played as Zan Sayonara Zetsubou Sensei Bangaichi (2009, two), and HenSemi (TV) (2011, 13) as Medaka Box Abnormal (2012, 12), which its alias "Abnormal Physiology Seminar" surfaced. So for such an entry a probed candidate is picked only when a name vouches for it: it is the title searched, or one of the show's names — its listing's title, the romanized name its search card carries (hianime's `data-jname`), or a name its entry page gives (the Japanese title and the synonyms rows) — is named by the entry (as above) or shares a name with one of the entry's titles, one starting with the other's name — at a word's end, or with a digit or 第 glued to it and no digit when the name itself ends in one, as a title starts with a name in the reader below — whatever follows it ("Gintama.: Silver Soul Arc - Second Half War" for "Gintama.: Silver Soul Arc 2"; "JoJo's Bizarre Adventure Part 6: Stone Ocean Part 2", whose name is "JoJo's Bizarre Adventure", for "JoJo's Bizarre Adventure: Stone Ocean Part 2"); a name with no words — a title that is nothing but a division — shares none. The year vouches for nothing on its own any more, and any other candidate is scored out as a refused candidate is: a pool rejected after scoring out a hit the year and count would have taken — one within the tolerance, or one from the entry's year listing fewer episodes than the entry has, which the airing rescue takes alone and the split stitching as a part — is the refusal by title the availability cache never persists; a scored-out hit nothing would have taken leaves the verdict as it was. The romanized name comes from the search page the walk already reads, and the page's names from the entry page the year filter already reads for every considered hit of a dated entry, so the rule makes no request the walk did not make before. Every one of the seventy-nine recorded dated picks with a count is still made: sixty-three are named by their listing's title; [Oshi no Ko]'s three seasons, listed as "My Star", by the name their card carries or their page gives (【推しの子】 on the first season's page); and thirteen by a name their listing's title shares with an entry title — the "(Uncensored)" JoJo listings, "Attack on Titan: Final Season, Part 1", Bleach's "Thousand-Year Blood War Arc" — of which only Gintama.'s second Silver Soul half and Stone Ocean Part 2 have no name on their card or page that would vouch for them otherwise. These names are evidence of the show and of nothing more: the rules that read a candidate's season and part read its listing's title alone and run before this one, so a page that writes a sequel's Japanese title without its season (Slime's second season, Stone Ocean Part 2) vouches for the show and leaves the season to them. What this rule does not refuse is a same-year show of the right length whose name another show's starts with — a short entry title ("Show") shares a name with every listing that goes on past it ("Show Other Thing") — which is the year and count's old reach, narrowed to the listings sharing a name. This rule leaves the countless pick, the single-video rule and an undated entry as they were.

The entry's titles rule which candidates can be picked, on either provider. Both these rules and the split detection above read one marker grammar: a marker word — season, part, cour or stage — with the ordinal after it ("Season 2", "Season Two", "Part 1+2") or a spelled ordinal before it ("2nd Season", "Second Cour"), an ordinal spelled as one standing alone ("Overlord III", never a bare number), and in Japanese 第N期, 第N部 or 第Nクール, with full-width digits read as ASCII and a number written in kanji read as the number it is. Every reader of a title's structure — the markers it ends on, its stem and the number the stem ends on, the ordinals it names, its reading, its name, its first number, what follows a broad listing's stem in it, and the part of a show it names past the show's stem — reads it without its *catalogue tags*: a release year or a format tag in brackets, a four-digit year ("(2020)", as the provider writes "Gintama (2011)" and "JoJo no Kimyou na Bouken (2012)") or TV, ONA, OVA or OAD ("(TV)", as in "JoJo no Kimyou na Bouken (TV)", "[OVA]"), brackets and tag alike ASCII or full-width ("（ＴＶ）", "（２０２０）"), wherever in the title it stands. So "Show Season 2 (2024)" ends on a season 2 and "Show Part 2 (TV)" on a part 2, as written without them. Where two titles are compared as written — the exact title the selectors prefer, one of the entry's own titles, a title that is a show's stem itself — a tag is kept: it is what tells a remake from its original, so "Hunter x Hunter (2011)" is not the title "Hunter x Hunter", nor "Fruits Basket (2019)" the title "Fruits Basket". Such a comparison reads a title as its structure without tags together with the tags it carries, wherever they stand, so "Show (2011) Season 2" and "Show Season 2 (2011)" are one title as written, and neither is "Show Season 2". A number in kanji is read as the number it is, compound ones included (第十期 is 10, 第十二部 12, 第二十一期 21, 第百期 100, and 第〇期 the zeroth); a run that writes no number that way (一二, 十十) is none. A kanji number is read where a Japanese number is expected — after 第, or before a counter — and nowhere else, so the 一 of a word like 一騎当千 is no number. A word ordinal runs from first to twentieth ("Seventh Season"), a word cardinal after a marker word from one to twenty ("Season Seven"), and a Roman numeral from II to IX; X is never one, being a word of its own in titles like "Spy x Family". Every reader of a title's tail — the markers it ends on, the one ordinal a later part's tail names, the stem — is a view of one parse of it. A candidate whose title ends on a season or part marker must name an ordinal one of the entry's titles names somewhere: in a marker, as any small number or numeral in it ("… Slime Datta Ken 2", "Mushoku Tensei II: Isekai Ittara Honki Dasu"), as a Japanese 第N, or as a number written before a Japanese counter (the ８ of "怪獣８号" or the 八 of "怪獣八号", before 号, 期 or 話). The kind of marker does not have to match, since the catalogues disagree on it ("86 Part 2" is hianime's "Eighty Six: 2nd Season") — but a candidate that names a season before the one an entry title carries, read past that title's stem as a sibling is read past W's ("Show Season 2" or "Show Season 2 Part 2" for "Show Season 3 Part 2"), or whose stem ends on a lower number of one or two digits after the same words ("Show 2 Part 2" for "Show 3 Part 2"; a year such as "Show 2020" is no such number), is the season before the entry and never picked, unless it is one of the entry's titles: like the entry before this one (below), it is scored out with a count, passed over without one, and leaves the clean miss the pool would be without it, and it still counts when the pool is read for a broad listing. An entry naming no season ("86 Part 2") keeps the allowance; one whose own titles disagree on numbering does not — for an entry known as both "Show Season 3" and "Show Part 2", "Show Season 2" is the season before; a first part or a span through it ("Final Season, Part 1", "(Part 1+2)") never disqualifies, any other span needs every part in it named ("Part 2+3"), while a zeroth one is an ordinal like any other ("Season 0" only for an entry that names 0); and only markers a title ends on count, so the story parts JoJo numbers mid-title ("Part 4: Diamond is Unbreakable") are not read as cours. A bare number of one or two digits that a title ends on, before any markers, is held to the same rule — "Show 2", the 2 of "Show 2 Part 1", the ２ glued to "ショー２" — since that is how a sequel is numbered as often as by a marker: "Overlord: Ple Ple Pleiades 2" is not Overlord, while "Kaiju No. 8" stays admitted for an entry whose titles name 8, a 1 never disqualifies, and "Mob Psycho 100" names no sequel at all. A title that matches one of the entry's titles only by carrying its first number with more digits after it — the words before the number alike, the number continued — is another show and is refused: "Show20" is not "Show 2", "Mob Psycho 1000 Part 2" is not "Mob Psycho 100 II", and "861" is not "86 Part 2". A title's first number is the first run of digits in the first word that holds any, so a separate word after it never lengthens it ("Kaiju No. 8 2nd Season" carries 8, "Show 2 (2020)" carries 2). A title carrying the entry's number itself, or the number another of the entry's titles carries after the same words, is not touched by this; a number another title carries after other words does not count ("Show20" is refused for an entry known as "Show 2" and "Other Name 20"). When every title of the entry reads as naming a division other than the first — a later season, part or number, a 0 included — a candidate that is one of those titles' names and nothing more, or that name followed by first divisions alone, as the reader below reads them ("Show", "Show Season 1", "Show First Half", "Show: Season 1" for "Show 2"), is the entry before it and is never picked, unless it is one of the entry's titles or carries the number one of them carries after the same words ("Show20" for an entry also known as "Show 20"): with a count it is scored out, without one it is passed over. A catalogue tag (below) is neither a word nor a mark here either, so "Show Season 1 (2020)" and "Show (TV)" are the entry before "Show 2"; any other bracketed words ("Haikyuu!! (Shin Series)") are words like the rest. The name is compared word by word, and the marks written right after it must be the title's own, a separator (":", "-", "–", "—", "~", ",", ".", "・", "、", their full-width forms, and a closing bracket around the name, as in "[Oshi no Ko] 2nd Season") counting as none, so "Steins Gate" is the entry before "Steins;Gate 0" and "Show Season 1" the one before an entry titled "Show: Season 2". The entry before names another entry of the same show, as the season before that the sequel guard drops does, not a refusal of what the provider calls the show: a pool rejected after it is the clean miss it would be without it. It still counts when the pool is read for a broad listing. A candidate that adds any other word to the name, or another mark right after it, is left to the other rules, so a provider's unnumbered name for a sequel ("Kaguya-sama wa Kokurasetai?", "Gintama'", "Haikyuu!! To the Top", "Steins;Gate Zero") is never refused for numbering alone, and an entry with any title naming no later division never refuses on this at all. With a count, a candidate the entry's titles refuse is still probed and stays in the pool as evidence — the split stitching above may stitch it as a later part, never as the lead — but it is never picked, rescued as an airing part, or counted as the pool's best distance, and its probe dying blocks no winner; without a count, a hit the titles refuse is passed over. When nothing the titles admit fits, the pool is rejected and the walk searches the next alias. This is what finds a first season the provider's search leaves out of the canonical title's results: hianime answers "[Oshi no Ko]" with its second and third seasons only, and its "My Star" comes back for "【推しの子】". Refusing by title is an inference from how titles are written, so a pool rejected because the titles refused a candidate the count accepted — or, without a count, refused any hit and nothing else was picked — is never the clean miss the availability cache persists: the walk moves on as it does from a pool of dead listings. Among candidates tied on distance, below an exact title match and above a positively matched year, a candidate whose part marker agrees with the part the entry's titles end on — no marker reading as the first part — wins, so "Season 2" and "2nd Season Part 2", twelve episodes each from the same year, are told apart for an entry that names no second part. Every selector keeps that order: an airing part rescued short of the count, the countless pick, the lead of a stitched chain among chains that fit equally well, and the rank a candidate whose probe died is weighed by — so a dying candidate whose part agrees makes the pick transient rather than handing it to one whose part does not.

The inverse of a split is one provider listing spanning two Kitsu entries: hianime lists a 22-episode "Attack on Titan Season 3" holding Kitsu's Season 3 (12) and Season 3 Part 2 (10), beside a 10-episode "Season 3 Part 2" of its own. A probed candidate is read as spanning this entry and the next when it carries the entry's own year, its title is admitted, it lists more than the entry has, and another candidate lists exactly the remainder while naming, right after its stem (a stem being the title with the markers it ends on removed), a division later than the broad listing's — a season above the one it carries, or a part above the entry's: "Part 2" in "Season 3 Part 2", "2nd Season", or the "Second" of Gintama's "Silver Soul Arc - Second Half War" beside "Silver Soul Arc". The spanning listing is then cut to its rows up to the next entry's first episode — the entry's own episodes and any recap tagged among or right after them — and scored as the exact fit it is; the candidate that completes it is the next entry and is never picked for this one, whether the cut is made or the entry's own listing stops it. The cut keeps the spanning listing's own numbers, which on hianime number the entry from 1, so it plays under that listing's key at offset 0. The later entry keeps its own listing; a spanning listing is never cut for it at an offset, since its key would then carry two numberings — offset 0 when played as the first entry and the first entry's count when played as the second — and the offset store holds one per key. The cut is made only when the entry is the spanning listing's head — the spanning listing carries the name one of the entry's titles carries, reads as that title does, and carries the same subtitle past the name and the same primes, with no conflicting release year — and no admitted listing of the entry's length is the entry's own beside it: one of the entry's titles, or a title that reads as the entry and carries the spanning listing's stem alone or opens what follows it with a division. That one stops the cut, even when the broad listing is exactly twice the entry's length. Any other exact-count hit, a spinoff of the franchise included, numbered or not, is no such evidence — admission says nothing about which show a title names — so the cut stands and wins, that hit kept just behind it. The decision tables below state the rule in full.

**One reading of a title.** The spanning cut compares titles through one reader, applied the same way to the entry's titles, to W and to every candidate. A title *reads* as the ordinals of the divisions it names, in order, from first word to last: a marker pair ("Season 2", "2nd Season", "Part 2"), an ordinal standing alone — spelled ("Second", "II") or a bare number of one or two digits ("Show 2"; "Mob Psycho 100" names none) — a Japanese division (第2期, 第2部, 第2クール, a word of its own or glued to the word before, each of several glued one after another — "ショー第2期第2部" reads `[2, 2]`), and a number of one or two digits glued to the end of a Japanese word ("ショー２"; the ８ inside "怪獣８号" is not). A division whose first ordinal is 1 is left out, being the whole ("Part 1", "Season 1", "First Half", "(Part 1+2)"). A Roman numeral or bare number right before a marker that carries its own ordinal is a division of its own ("Show II Part 2" and "Show II Part Two" read 2, 2); an ordinal written with a suffix or spelled out forms the pair with the marker after it, so "3rd Season Second Half" is a third season and a second half. So "Show 2", "Show 2nd Season" and "ショー 第2期" all read `[2]`; "Show", "Show Part 1" and "Show First Half" read `[]`; "Lucky 2 2nd Season" reads `[2, 2]` and "Lucky 2" `[2]`. A title's *name* is its words up to the first division it names, with what a Japanese word holds before a division glued to it — a word ordinal standing alone ends the name only where nothing but divisions follows it, so "The Seventh Son" is named "The Seventh Son" while "Gintama 2nd" is named "Gintama": "Show", "Show 2", "Show 2nd Season Part 2" and "Show II Part 2: Arc" are all named "Show", "Other Show Season 2" is named "Other Show", "ショー２" is named "ショー"; a title that opens on a division ("86") is named by its stem. A title *reads as the entry* when it reads as one of the entry's titles does and starts with that title's name — at a word's end, or with a digit or 第 glued to it, no digit when the name itself ends in one ("Mob Psycho 1000" does not start with "Mob Psycho 100") — so "Other Show 2nd Season" does not read as "Show 2", and "Show 2nd Season" does not read as "Showtime 2". The entry *names* a title — and *heads* it when the title is a W — when one of its titles, the same one for all three, carries the title's name, reads as it does, and carries the same words past that name outside their divisions, the subtitle a title adds after a division: reading alike under another name ("Other Show Season 2" for "Show Season 2") is another show, and so is a subtitle the entry's title does not carry. "Show Season 2" is named by "Show 2nd Season", while "Show 2nd Season: Extra Arc" is not, nor "Show 2" by "Show 2: The Movie". A title with no division has no such words, its name running to its end. Words alone drop the two marks that tell shows of one name apart, so the two titles must also be written with the same primes and carry no conflicting release year: "Gintama" is not named by "Gintama'", nor "Film (2019)" by "Film (2020)". A prime is an apostrophe, however it is written, that ends a word, so "Gintama′" is named by "Gintama'"; one that opens a word — a single quote opening, an elision — cancels one that ends a word, so "Show 'Arc'" carries none and "'Tis Time" none either, and one inside a word ("JoJo's") is no prime. An apostrophe that ends a word is a prime whatever it means there — a plural possessive ("Girls' Last Tour") reads as one, and a title written without it is not named by it. Release years conflict only when both titles carry one and they differ: a year one catalogue leaves off names no other show, so "Hunter x Hunter" is named by "Hunter x Hunter (2011)", and a remake and its original written that way are told apart by their years and counts. Every other mark — an exclamation or question mark, a period, a decorative symbol, quotes single or double, a slash, a wave dash in any form — is drift between catalogues and is not compared ("Haikyuu" for "Haikyuu!!", "Lucky Star" for "Lucky☆Star"), and neither is a format tag, the format badge speaking for it. A title's *stem* is the title with every marker and Japanese division it ends on removed, Japanese ones stacked one after another included ("ショー 第2期 第2部" → "ショー"); a bare or glued number it ends on stays in the stem ("Lucky 2", "ショー２"). A title that does not start with W's whole stem is read past it without that number, the number then one of the divisions W ends on: "Show Season 3" names a season 3 past "Show 2" as it does past "Show 2nd Season", and "Show 2nd Season" opens what follows "Show 2"'s stem with the season 2 W itself names. A title whose number where W's stands only continues W's — the digits of W's number as a number, any zero padding W writes it with aside — ("Show 20 Part 2" or "ショー２０第2部" beside "Show 2" or "ショー２"), or is lower than W's, is not read past it; the same number written apart ("ショー ２" beside "ショー２") is, and so is a higher one that does not continue it ("Lucky 3" beside "Lucky 2", the next season, as "Show Season 3" beside "Show 2" is; "Show 21" continues "Show 2" and is not). What *follows W's stem* in a title is what comes after it at a word's end, or after a number or 第 glued to it ("ショー２", "ショー第2期"); "Showtime 2" does not start with "Show", and a stem that ends in a digit takes no further digit glued to it, so "Show 20 Part 2" does not start with "Show 2", nor "860" with "86".

| Tsubu★Doll (5, no year, OVA) | a TV series (ruled out by format), a two-episode OVA, seven others | the OVA sits within the tolerance and nothing names it: refused | nothing |
| Yi Ren Zhi Xia 6th Season (26, no year) | "The Outcast 5th Season" 12, "The Outcast 6" 26, a movie 1, a special 2 | "The Outcast 6" is named by the alias "The Outcast 6th Season" | The Outcast 6 |

Names are compared as written: the entry's titles have to carry the provider's name for the show for its broad listing to be read at all, which Kitsu's titles do for every recorded pool ("Gintama.: Silver Soul Arc" among Shirogane no Tamashii-hen's). The title rule that admits a candidate weighs only the divisions a title ends on and never its name, because the provider answers an alias with titles that share no words with the canonical one ("My Star" for "[Oshi no Ko]").

Not decided by this rule: what follows the divisions a title opens with is read like the rest of it, so "Show 2nd Season Recap" reads `[2]` and is "Show 2"'s own beside "Show". One shape is recorded in `docs/deferred-work.md` instead: a broad listing completed by a sibling written in another script is never cut. A title that extends the entry's name after it still starts with that name, while one that extends it before does not: for "Show 2", "Show Other Season 2" (12) beside "Show Other" (24) reads as the entry and plays, while "Other Show Season 2" (12) beside "Other Show" (24) is an L and nothing plays. Which of the two a provider's subtitle is cannot be told from the words, and the table leaves the first as it stands.

So a numbered spinoff ("Show Side Story 2") or a recap of W's own season ("Show Season 3 Recap") never completes a span, and a spinoff never stops one.

**Choosing among candidates** — part agreement sits in every selector's order, below an exact title where the selector reads one, and the provider's order breaks only a full tie. Copies of the winner under a version tag are not chosen between at all: they are the pick's versions (see [Versions of one pick](#versions-of-one-pick)). Without a count, a hit nothing but its position vouches for is never the countless pick (below): its page is read, and nothing more. Every selector chooses only among candidates that could be picked — a broad listing cut to the entry's episodes included, so a W that is another entry of the same show is never cut: a candidate the entry's titles refuse, another entry of the same show (the entry before this one, or the season before it), or, for an entry one video long or one with a count and no year, a probed candidate nothing but its count vouches for, or for a dated entry with a count above one, a probed candidate no name vouches for (above), is in none of them — never a winner, never rescued, never a chain's lead, never the countless pick, and its probe dying blocks no winner, though it still leaves the pool unheard:

| Selector | Order |
|---|---|
| Winner (candidates at the best distance) | exact title, part agreement, matched year |
| A dead candidate's rank | the same, among candidates that could be picked |
| Airing rescue (confirmed, short of E) | distance, exact title, part agreement |
| Countless pick | exact title, then part agreement, then matched year — below the exact title, only a hit its own year or the entry's name vouches for |
| Stitched chain | fit to E, then a lead whose part agrees |

When Kitsu's episode count is unknown (rare, but happens for upcoming shows), the countless pick takes an exact title match; failing one, a candidate whose part agrees with the entry's comes before one naming another part, and within each a candidate whose year matched comes before the rest, the provider's order breaking ties — among the candidates something vouches for. Failing an exact title, a candidate is taken only when its own year is the entry's or the entry names it — named, read, subtitled and primed as one of its titles, with no conflicting release year, under any alias ("Dragon Ball Super: The Galactic Patrol" for an entry searched as "Dragon Ball Super: Ginga Patrol", "Show Season 2" for "Show 2nd Season"). A hit the year merely tolerated — one year off, the December allowance, or with no year on its page — is taken on its name or not at all, whether the year disproved some other hit in the pool or none, and an entry with no year, which nothing can match or disprove, takes a hit on its name alone. A pool without such a hit is the plain miss: the walk searches the next alias, and a walk that finds nothing is the clean verdict. Unlike a refusal by title, which overrides a hit the count or the year left standing, nothing here vouched for any hit — no count, no year, no name — so the miss is the clean one a pool the year showed to be token-search garbage already answers; an announced entry's negative row lasts no longer than its status allows before the probe runs again. An entry known only by titles in another script than the provider's has no hit it names, and is refused the same way unless a hit's own year is the entry's. An announced sequel the provider does not list yet — Dragon Ball Super: Ginga Patrol, with neither a count nor a premiere date on Kitsu, or a subtitled sequel announced for the year after its series, whose searches answer with the series alone — is so refused rather than resolved to the series its searches answer with, or to the remake or spinoff the next alias turns up. Of hianime's entry pages, every one read of a show airing in the ordinary way named a year; the few that name none carry no Aired row at all — placeholder and duplicate listings, an announced show — so a hit without a page year is rare, and the name is what vouches for it. A candidate whose listing answers with an error status gives way to the next. The frontend treats this as a soft signal and still renders the card; the lazy click path will surface a real error if the bridge picked wrong.

Two verdicts of absence are the ones the availability cache may persist as a negative row: a walk in which every search completed and nothing matched, and the probe's answer that a show it found is listed without the requested mode — a listing with no rows, or a sampled row that lacks the mode. Transport failures, upstream refusals, failed probes, and a mode nobody answered for — every sampled row saying nothing either way — are transient and write nothing, so a real show can't hide behind the negative TTL.

### Versions of one pick

hianime lists some seasons twice: an older listing whose title ends on "(Uncensored)" — or "[Uncensored]", "[UNCENSORED]" — and a plain re-upload of the same season under the same title without it. Every JoJo season up to Golden Wind is listed so ("JoJo's Bizarre Adventure (Uncensored)" beside "JoJo's Bizarre Adventure", 26 episodes each, numbered alike), and a search for the word answers with some thirty other tagged listings besides (Redo of Healer, Chained Soldier, Tokyo Revengers among them). The tag is the only version tag the provider's titles carry: on 2026-10-16 its search answered "director's cut", "uncut", "remastered", "(BD)" and "re-edit" with no such listing, the one "Remastered Edition" it lists being part of a title rather than a tag. Before versions, the picker chose between the copies as between any tied candidates — by a matched year, or by the provider's order — so which copy played was an accident of the pool.

When the pick by count has its winner, every candidate that could be picked at the winner's distance is read for copies of it: a candidate is a *copy* when its title is the winner's once a bracketed version tag is set aside — compared as written, case and spacing aside and catalogue tags kept, the tag read in ASCII or full-width round, square or lenticular brackets, in any case — its format badge is the winner's, and its listing numbers the same episodes, each with the same number and tag. When the winner and its copies are under different version tags, one each, they are the pick's *versions*, in the provider's order, and the one tagged "(Uncensored)" plays unless the request names another; the answers that carry the pick — availability and play — name each version by its kind (`uncensored` or `standard`) and its show key. Anything less certain is one pick, exactly as before:

| Case | Outcome |
|---|---|
| Both copies probed, the same count and numbering, both could be picked | versions; the uncensored copy plays |
| The same, the plain copy the exact title searched (Golden Wind's alias "Jojo's Bizarre Adventure Part 5: Golden Wind") | versions; the uncensored copy plays |
| The same, one copy's page year matching the entry's and the other's one off or absent | versions — both survived the year filter, and a copy's year tells no season from another |
| A copy whose page year the filter excludes | no candidate, so one pick |
| A tagged copy with another count, or the same distance from the other side (11 and 13 for 12), or numbered otherwise | one pick, chosen as before |
| A tagged copy under another badge | one pick |
| "Uncensored" written outside brackets ("Show Uncensored") | a word, no tag: one pick |
| A tagged listing of another title ("Show Other (Uncensored)" beside "Show") | one pick |
| Two listings under one tag beside the other copy | which pairs with which cannot be told: one pick |
| Only one copy listed, tagged or not | one pick |
| A plain copy the title rule refuses — the tag hides a season marker from the rule, so "Show Season 2 (Uncensored)" is admitted for "Show" while "Show Season 2" is not | one pick: the tagged copy alone, as before |
| An entry with a count and no year: the tagged copy is not named by the entry's titles, since the tag's words follow the name | the tagged copy is scored out: one pick |
| Only the plain copy probed, the tagged one past the probe head (or the other way round) | one pick, as before |
| The airing rescue, the countless pick, a stitched pick, a cut broad listing with every copy heard | one pick, as before |
| A copy whose probe died unheard, one every rule would have let be picked — the pick by count, a cut broad listing included | the pick is transient, as when a stronger candidate dies: playing one copy now and the other once the dead one answers would split the show's history across two keys on the strength of weather |
| A copy whose listing answered not-found | positively gone, a dead listing like any other: one pick, as before |
| A dead copy no rule would pick — for an entry with a count and no year, or one video long and no year, a tagged copy the entry's titles do not name | blocks nothing: one pick, as before |

Every other rule reads a tagged title as it did: the tag is bracketed words, not a catalogue tag, and only this rule sets it aside. The probe head is not widened for copies: every recorded JoJo season's first answering pool holds both copies inside the head, a copy past it costs nothing but the choice — the pick plays as before — and widening the head would cost probes on every pool for listings that are rare.

Each version is its own listing with its own show key, so history, numbering stamps, watched-at stamps and the reverse mapping keep a row per version played. Each version's numbering is read from its own listing too: the tags an earlier version of the app gave its rows (see [Episode numbers](#episode-numbers)), the stamp a request by a former number is read through, and the stamp a listing at hand puts right: a play, a download, a range download and a probe each put every version's stamp right from that version's own listing, not only the stamp of the copy they read. The detail page offers the versions when the availability answer names more than one, Uncensored selected unless another was chosen. The renderer remembers the version chosen for an entry, on this computer, and names it on every play, download, external-player and Syncplay request for that entry — from the detail page, the play page and a Continue Watching card; choosing Uncensored again forgets the choice, and a request naming no version plays the uncensored one. A request naming a version the pick does not carry plays the pick. The provider need not carry one audio mode for every copy of a season, so the availability probe asks each version whether it carries the mode requested — the pick's own answer, and one mode probe of each other version's rows, the same bounded scan — answers available when any version carries it, absent only when every version answered absence and unknown otherwise, and says of each version whether it does — another version's probe failing leaves that version's mode unknown rather than failing the answer, which a block or a gate refusal still does, and an answer left unknown that way moves the walk on to the next provider as any inconclusive mode answer does; a play's stamp of the row keeps what the probe said of each version. The detail page offers only the versions not said to lack the mode, none when one is left. A play, a download, or each episode of a range download, whose version answers a dead end for the episode in its mode plays it from the pick's next version that carries it, in the provider's order — a range starting each episode from the version it names — and a play names the version that played, as every record of what served does: a download's file, a range's files episode by episode, the history row of a play or a hand-off (a download records no watch, so it writes none), the resolution-cache row and the played version a stamp marks (a range's, the copy that served its first episode); each further version costs its own episode chain, asked only after the one before it dead-ended. The reading of a listing's appended extras ([Episode numbers](#episode-numbers)) is made of the version the walk reads — the one a play names, the default for the availability probe and a range's start — and holds for every version of the pick numbered by position and the same length, each the same episodes under its own ids, so a version chosen later carries the same extras; a reading kept for one version stands for another when the evidence cannot be read.

## Episode caps

The picked show's episode list arrives with the probe, so the availability cap is the highest listed episode number, normalised to the entry's own numbering — a continuation cour a provider lists with the franchise offset, as anidb.app did, has the offset subtracted — with no second fetch from the provider and no approximation. The cap is an integer. A recap row keeps a fractional display tag (`number2`: a `7.5` the listing numbers a recap with on hianime, where the row's position is its slot and the site's number its tag), and the resolver surfaces those as playable extras beside the cap rather than inside it. Providers can number differently — anidb.app counted continuously across a franchise's seasons, hianime counts within each season-split entry — which is why the cap is stamped per provider and never compared across them. A stitched pick's cap is counted across its parts, in Kitsu's numbering, and a cut spanning listing's cap is the entry's own count. Rows a provider appends after a show's last episode, when the evidence below proves them extras, are tagged as extras and stay out of the cap (see [Episode numbers](#episode-numbers)).

## Episode numbers

Several sources number a show's episodes, and they do not always agree about a recap or a special.

- **Kitsu's episode list** labels the tiles. Its rows carry whole numbers only (`number`, and `relative_number` within a season), and a tile takes the title, thumbnail and air date of the Kitsu row with its number. Where Kitsu counts a recap, it is a regular episode in that list.
- **AniList** fills in thumbnails Kitsu lacks from `streamingEpisodes`, matched by the whole number in the episode's title ("Episode 8"; a "7.5" is skipped), and gives the aired count the strips grey tiles past.
- **The provider's listing** decides what plays. Each hianime row has a slot (its position), the title the site lists it under, and, when it differs, a display tag (`number2`): a recap between 7 and 8 sits in slot 8 tagged `7.5`, and every row after it carries its own number as its tag. Availability reports the highest whole tag as the cap and the fractional tags as `extra_episodes`, translated to the entry's own numbering by the continuation offset (above). A request for a whole episode N plays the row whose display number is N (plus the offset) — its tag where it has one, its slot where it has none — so after a recap it is never slot N; a request for `7.5` plays the row tagged `7.5`, unless it names a stitched recap by the tag an earlier version gave it (below).
- **History** records the app's own number for the episode a play resolved to — the number it asked for, unless that named the row by a number it no longer carries — marked as such, and reads it back as it is ([architecture](./architecture.md#watch-history-and-removing-it)). Rows from before the marker hold the provider's number for the episode and read back through the numbering sidecar — the show's offset and one (slot, tag) display stamp — which no resolve moves to another row. Warms stamped too, so a row past a recap whose stamp a warm moved before then reads one episode high until its show is next watched. A read of such a row takes the sidecar in one read, offset, stamp and former tag together, since a repair of the stamp (below) takes no history guard.
- **aniskip** is asked by MAL id and the tile's whole number; **tracker progress** is the tile's whole number, fitted to the tracker's own total (below).

The app's own number for an episode is the tile's: Kitsu's whole numbers, plus the provider's fractional extras as tiles of their own beside the episode they follow (a `0.5` beside episode 1). A whole episode is requested, resumed and recorded by that number, and sent to the trackers by it fitted to the tracker's total (below); a fractional extra is requested, resumed and recorded by its own number (`7.5`), asks aniskip for nothing, and moves no tracker progress, since aniskip and the trackers count whole episodes. Prev and next step from a recap to the whole episodes either side, through any other extras listed beside the same episode first.

A stitched listing numbers a recap before a part by where it sits in the entry: a later part numbered on from 13 that opens on its own `12.5`, a recap before its first episode, places it between episodes 12 and 13 of the entry, tagged `12.5`. Two recaps between the same episodes — the part before ending on one, the next opening on another — cannot share a tag, since a request names one row: the first keeps it, and the next takes the tag halfway on toward the next episode (`12.75`, then `12.875`). An earlier version tagged a cumulatively numbered part's opening recap a part later (`24.5`), and gave the second of two such recaps the first's tag, so a stitched row remembers the tag it had then. So does a single listing's recap at its continuation offset — a continuation numbered on from 13 that opens on `12.5`, the entry's `0.5` now: an earlier version advertised it as `12.5` and asked the provider for `24.5` by that name, and `24.5` is the tag it remembers. History rows, sidecar stamps, kept positions, downloads and requests from that version can still name such a recap by its old number:

- **The sidecar stamp** is put right from any listing of the show at hand — a play's resolve or warm, an availability probe that finds the show (the Continue card's among them), a download's resolve or a range download's pick, each before it caches the availability row or resolution it stamps, since a probe that takes a cached row reads no listing to put the stamp right from: a stamp naming a row by its former tag names it by its tag now, and keeps the former one in two more columns after it — unless a row of the listing carries that tag now, since what is kept under it may be that row's. A build that reads four columns ignores the two and drops them when it rewrites the row; such a build reads the repaired stamp by the recap's tag now, which its own listing gives another number, and is not supported against the same history.
- **A request by the former tag** goes to the row the stamp names while the stamp still names it so; failing a stamp, a row tagged so now wins, and failing that, the row that had the tag before.
- **The session** a play opens names the episode it plays and the number that episode had before, unless a row of the listing carried that number when the episode was resolved; a replay names the ones its cached row recorded. The player numbers, steps from and keeps its position under the episode played, and a position kept under the number asked for or the former one moves to it; where one is kept under the episode played already, that one stays and the other is dropped. A resolve the request named by the former tag is kept in the resolution cache under the episode it played, so the tag answers for the row that carries it now.
- **Continue** reads its row again once the card's match is known, and again after its probe or a retried probe has answered, moving a position kept under the number the row names as its former one before the card is offered again, and a click reads it again once its cap is settled; when nothing measured the cap and the row reads as a fractional episode, the click first warms that episode, a resolve that records no watch, so a listing has put the row right before it is read. It goes on from the episode the row reads as then, and a position kept under what the row read as before moves to it. The detail page reads its resume row again once the row has arrived and an availability lookup has answered, in either order, and again for each later lookup and after each warm of the show or cap re-probe answers — a Play or Download clicked while it is being read again waits for it, busy and for a bounded time — warming a fractional row first when the lookup measured no cap, and moves a position kept under the number the row names as its former one. Each marks watched the episode the session plays.
- **A download** is named for the episode it plays, and a file in the folder under that episode's former number is the episode, already there — unless a row of the listing carries that number now.

### Extras appended after the last episode

hianime lists some shows' OADs and web-only episodes as further whole-numbered rows after the last episode: Noragami's two OADs are rows 13 and 14 of a twelve-episode show, Noragami Aragoto's two follow its thirteen, and Satsuriku no Tenshi's four web-only episodes follow its twelve. Read as episodes they would be tiles 13 and up, raise the cap past the show's end, and move the trackers' progress for rows they do not count. When the evidence proves the rows are not episodes of the show, they are read as extras instead: tagged `12.1`, `12.2`, … beside the last episode, in listing order, each row otherwise the row it was. The evidence, every piece of which must hold:

- the picked listing is a single provider listing, numbered by position with no tags at all (a recap's fraction or a continuation's offset means another reading is already in force), and runs one to nine rows past Kitsu's count. A stitched listing is never read this way: its parts, numbered from 1, stitch into untagged rows numbered by position like a single listing's, and the chain stitches parts whose sum fits the count within the tolerance, so rows past the count there are the later part's own episodes. A cut spanning listing is cut to the entry's own episodes and runs no whole episode past the count (a recap it keeps after them is tagged, which the shape check turns away);
- Kitsu calls the show finished at that count, and AniList, for the MAL or AniList id Kitsu maps it to, ends it at the same count with nothing left scheduled;
- Kitsu's rows for the count's last three episodes (all of them for a shorter show) are there, dated and named, none lists an episode past the count, and the read reaches as far as one would be: the page after the last one holding the count's episodes is read too, since Kitsu's pages are not always dense;
- the listing names each of those three episodes as Kitsu does — letters and digits compared, case aside — and at least one of those names is more than a number, so its numbering is Kitsu's up to the count;
- every row past the count has a name of its own: not missing, not only its number ("Episode 13"), and neither one of Kitsu's episodes nor one on the first episode page of a TV entry Kitsu relates the show to that has aired, whatever it calls the relation — its sequel, its prequel, a spinoff it files as `other`, since a TV entry's episodes are what a provider merges into a listing — whose page must carry a title for each of its first episodes, as many as there are rows past the count, since those are the episodes the rows would be; Kitsu's pages for second seasons are sparsely titled — of the ones recorded, several title no episode and one only the first — and a title says nothing about an episode it does not name;
- Kitsu, its relations read whole, relates the show to a finished OVA, ONA or special exactly as long as the rows past the count, whatever it calls the relation — Noragami's two-episode OVA, a side story; Satsuriku no Tenshi's four-episode ONA, which Kitsu calls its sequel — and to no entry airing now, whatever the role and whatever its format (a music video aside): a non-TV entry's page is never read, so nothing but its airing tells its cour from extras — Stone Ocean Part 3's sequel is an ONA Kitsu calls current. A TV entry Kitsu only announces (upcoming, tba, unreleased) has aired nothing and is passed over, its page never asked for — Kitsu answers one with placeholder rows, and a request the read does not need could still fail it. No other relation's page is read: the OVA, ONA or special that explains the rows is what the rows are, and Kitsu titles its episodes as the provider titles the rows — Satsuriku no Tenshi's ONA exactly as hianime titles its web episodes, case aside — so holding those titles against the rows would refuse the very readings the rule exists for.

The last two are what keep a TV sequel's cour out. hianime lists some entries with the next cour merged in — Attack on Titan Season 3 with Part 2, Gintama.'s Silver Soul arc with its second half, Haikyuu!! To the Top with its second cour — and while that cour aired the listing ran a few rows past the entry's count with every other piece of evidence holding. Those rows are the TV sequel's episodes, and the rule never reads them as the entry's extras: an airing TV entry refuses, and an aired one's titles are checked against the rows — a prequel's and a spinoff's as a sequel's, since Kitsu relates The Slime Diaries to Slime's first season as `other` and Noragami to Noragami Aragoto as its prequel. A finished OVA, ONA or special of exactly that length is read as the extras whatever Kitsu calls it, as Satsuriku no Tenshi's web episodes are.

Anything short of the evidence leaves the listing exactly as it was picked: a show still airing, where the provider may simply be ahead of Kitsu; a count Kitsu or AniList does not give, or gives differently; a long runner Kitsu stopped counting; a listing whose titles do not line up; rows nothing on Kitsu explains. The evidence is read only for a listing of that shape, from the cache where it is there — a detail page visit leaves Kitsu's entry and first episode page; AniList's airing answer lasts three hours for a finished show — and from Kitsu and AniList where it is not: Kitsu's entry, the pages holding the count's last episodes, the entries Kitsu relates the show to, each aired TV relation's first episode page, and AniList's airing answer, within five seconds for each pick. A request with no Kitsu id behind it has none.

A reading the evidence proves is kept for thirty days with the show's slug and the ids of the rows it tagged (`appended:v2:<kitsu id>`); a reading kept before the name check read every related TV entry (`appended:v1:`) is not read, since the narrower rule may have proved what this one refuses. A request whose evidence cannot be read — AniList limiting, Kitsu down, the five seconds spent — reads the listing the same way when its rows past the count are those very rows; evidence that reads and no longer proves the reading forgets it, and so does a listing of the show that no longer runs past the count, as when Kitsu recounts the show to take the rows in, or that the split chain now stitches from several. A cold first read can outrun the five seconds; it then reads nothing and keeps nothing, and each later read gets further, since every piece read in time is cached. Availability, the embedded player, the external-player and Syncplay handoff, a single download and a range download all read the listing this way, since each stamps the availability row with the cap and extras its own resolve saw. Of the 113 shows recorded under `tests/fixtures/hianime/appended/`, the three above are the ones it moves.

A fractional tile Kitsu has no title for — which is every one, since Kitsu names whole episodes only, so a recap's `7.5` as much as an appended `12.1` — is named "Extra 12.1". An appended extra is requested, resumed, recorded and skipped by aniskip and the trackers as any fractional extra is (above), and stepping from an extra goes to the next or previous extra beside the same episode before the whole episodes either side, so Satsuriku no Tenshi's four web-only episodes play one after another. Availability rows and cached resolutions written before this reading are not served, since either can hold an extra as a whole episode: the keys moved past them (availability to `v20`, resolutions to `v21`), and the recaps renumbered above moved them on (to `v21` and `v22`). Rows written while the name check read a TV sequel alone and a stitched listing could be read for extras can hold as an extra what is now a whole episode, so the keys moved on again (availability to `v23`, resolutions to `v24`), beside the kept reading's `appended:v2:`. A history row is kept as written; one an earlier version wrote for such a row — slot 13, played as episode 13 — reads back as `12.1` while the reading is kept for the row's Kitsu entry (the one it records, the one a lookup claimed it for, or the one its show id maps to), and as episode 13 otherwise.

Beyond the continuation offset and appended extras, nothing reconciles Kitsu's numbering with the provider's. When they disagree about a recap:

- **The provider lists a recap Kitsu does not** (hianime's `7.5`): every whole tile carries Kitsu's label and plays the provider's episode of that number, and the recap is a tile of its own.
- **Kitsu counts the recap as a regular episode the provider lists as `7.5`** (Kitsu's 8 is the recap, the provider's 8 is Kitsu's 9): tile 8 carries the recap's Kitsu label but plays the provider's 8, every later tile is labelled one episode early, and Kitsu's last episode is past the provider's cap. The recap plays from its own `7.5` tile.
- **Kitsu counts a recap the provider does not list**: the same one-early labels after it, and Kitsu's last episode past the provider's cap — a greyed tile where the strip reaches it, none where the strip stops at the cap — with no recap tile.
- **MAL, or AniList's streaming list, counts a recap Kitsu does not**: from the recap on, aniskip's skip times and AniList's backfilled thumbnails are one episode early in that list (tile 8 gets the recap's), since both are asked by the tile's number.

The trackers keep a count of their own, and the write-back reads it — MAL's `num_episodes`, AniList's `Media.episodes` — in the request that already reads the user's row before a write:

- **The tracker counts more episodes than Kitsu**: AniList counts 13 episodes of Air, the first of them a prologue, where Kitsu, MyAnimeList and the provider number 12 — the same holds for Fate/stay night: Unlimited Blade Works, Saekano, Kimi ni Todoke 2nd Season, Tales of Zestiria the X and High School DxD Hero; a long show's tracker may count recaps the provider lists as 0.5s; AniList's Haruhi (2009) counts 28, the whole series in story order, against Kitsu's 14. The count alone does not say which of these the extra episodes are, so the gap is not filled: every tile sends its own number, and the last episode of a finished show sends its number without the completed status, leaving the tracker's row short of its total.
- **The tracker's entry is shorter than Kitsu's show** (AniList splits Ranma ½'s 161 episodes, which MyAnimeList counts as one entry, into an 18-episode entry and a 143-episode sequel): nothing past the entry's end is sent, and, the totals differing, no completed status either.
- **The totals agree**: the tile's number is sent as it is, and the last episode of a finished show completes the row.
- **The tracker's total is unknown** (AniList's `null`, MAL's `0`, as for many airing shows): the tile's number is sent as it is, and the last episode of a finished show completes the row, as it did before the total was read.

Only Kitsu's own last episode of a finished show can complete a row: an episode the provider lists past Kitsu's count, and not read as an appended extra (above, which sends nothing), sends its number, clamped to a known total, and no completed status, whatever the tracker's total — its place in the tracker's numbering is as unknown as a count gap's. An airing show whose tracker total is known is clamped to it like any other. A watched episode never moves a tracker's progress backwards, and a rewatch's last episode sends no completed status, so the row stays a rewatch. These describe what the app sends: a tracker may apply rules of its own on receiving it. The detail page's list editor writes what the user sets, as it is.

## Kitsu → MAL and AniList via the mappings endpoint

The Kitsu API exposes its known third-party ids on the `mappings` relationship of an anime resource. The backend queries `GET /anime/:id?include=mappings` and walks the `included` documents for the ones whose `attributes.externalSite` is `"myanimelist/anime"` or `"anilist/anime"`; their `attributes.externalId` values are the MAL and AniList ids.

The ids are cached per Kitsu id (`kitsu:external-ids:v1:k<id>`): for 30 days when both the MAL and the AniList id are present, for a day when either is missing, since Kitsu adds the missing mapping for a fresh seasonal show within days. A read that fails is not cached. Everything that starts from the mappings — tracker id-resolution, the airing schedule, the banner and episode-thumbnail backfills, aniskip — reads them through that one cache, so a detail page with two trackers connected asks Kitsu once for the show rather than once per tracker. The detail row with its backfilled banner and the episode-thumbnail map are still keyed by the Kitsu id on top of that, so a hit there skips the AniList lookup as well.

The translations AniList makes between its own ids and MAL's are cached the same way, one row per id in each direction (`anilist:media-id-for-mal:v1:<mal id>`, `anilist:mal-id-for-media:v1:<AniList id>`): 30 days for an id AniList translated, a day for one it does not index, nothing for a failed request. The tracker accounts need them whenever Kitsu maps a show to one tracker only — the AniList account keys on AniList's `mediaId`, reached from a MAL-only mapping through `Media(idMal:)`; the MAL account keys on the MAL id, reached from an AniList-only mapping through `Media(id:){ idMal }` — and the Watch Later rail's batch translation writes every id it learns into the same rows. Each is a public AniList request against the 30-per-minute budget the rest of the app shares, which is why none of them is asked twice for the same id.

## What this enables

- **Trending Now** uses AniList's `TRENDING_DESC` sort, then bridges each MAL id back to a Kitsu id so the rest of the renderer can treat the row uniformly with Kitsu-sourced rows.
- **Banner backfill** — when the detail page sees a null `coverImage` from Kitsu, it asks AniList for `bannerImage`, by MAL id when Kitsu has one and by AniList id otherwise, retrying once by AniList id when AniList has no media for the MAL id. Roughly half of any week's currently-airing top 20 shows hit this fallback path.
- **AniList banner beside the cover** — the trending query already returns every entry's `bannerImage`, so each bridged entry keeps it alongside Kitsu's cover, and it is remembered per Kitsu id for thirty days. A detail page for a show the trending row has listed reads that remembered banner and makes no AniList request for it — when Kitsu has no cover, the banner backfill takes the remembered banner too; a show never listed has none remembered, and its detail carries a banner only when that backfill fetched one. An AniList trending answer that lists an entry without a banner forgets the one remembered for it. A rate-limited or failed trending fetch falls back to Kitsu's list, which carries no banners, and leaves the remembered ones as they were. A banner whose URL the image proxy has found gone (an upstream 404 or 410) is not offered again for thirty days: the next trending fetch drops it from the row, the next detail read forgets it, and the null-cover backfill — which still asks AniList, since a replaced banner would arrive as a new URL — refuses the same URL back.
- **Episode-thumbnail backfill** — episodes Kitsu has no still for take one from AniList's `streamingEpisodes`, reached the same way: MAL id first, AniList id when there is no MAL mapping or AniList has no media for the MAL one — provided the listing describes the show; see [Streaming listings that are not the show's](#streaming-listings-that-are-not-the-shows).
- **aniskip** lookups need the MAL id to query, and the same Kitsu→MAL mapping is reused.
- **Availability** can answer "is this in the catalogue in the requested mode?" by running the same walk the play path would and caching the verdict per `(kitsu_id, mode)`, naming the provider whose catalogue answered.
- **Continue Watching** reads each history row's show from the row itself: a watch records the Kitsu id of the page it was played from in the row's last column, and a row carrying one renders that Kitsu entry with no matching, search or enrichment — unless Kitsu answers that the entry is gone (a 404 or 410), when the row is matched as a row without an id is; any other failure to read it (the network, a 5xx, a rate limit, a timeout) renders the row unmatched for that load and leaves its id alone. A play from the detail page, the play page, an external player or Syncplay all record it; a resolve that played nothing does not, and neither does a watch whose provider title names a different cour than the Kitsu entry's slug. Rows written before history recorded the id fall back to matching them back to Kitsu. A play from a Continue card records the card's entry only when the match is one the user stands behind — the id the row recorded, or a mapping a play stored — and a play page opened from a card whose match was a guess (a title match, a search pick, a guessed mapping, or the fallback of a row whose recorded entry is gone) keeps that guess off the row too for the session's whole life — the verdict travels in the session's own URL, through its episode switches, while a session opened from the detail page records its id whatever the home page guessed — so one click cannot pin a wrong guess for good; a guessed session also writes nothing to the user's tracker accounts (AniList, MyAnimeList), while the episode's position, which stays on this computer, is kept under the guessed entry as under any other; such a row gains the id when the show is played from its detail page. The detail page's resume finds a row whose recorded entry is gone too: a 404 or 410 from Kitsu's detail fetch — only one something already asked for, such as the home page reading the row's id — marks the id gone in the cache for a year and drops the id's cached detail, unless Kitsu served the id after that fetch began; a later fetch that serves it clears the mark, from the cached detail or from Kitsu — a fetch Kitsu serves clears it in one step with caching the detail, once its banner backfill is done, and does neither if a fetch begun after Kitsu served it has been answered gone meanwhile, reporting the entry gone instead, and a fetch that cannot clear the mark fails rather than load the entry as live — the detail page's resume lookup runs beside its detail fetch, and whenever it finds no row it asks again once the fetch has served the entry, so the visit whose fetch clears the mark resumes too; for a show never watched that is one more lookup of the local history — removing the show from history takes the marks of the ids it was known by that no remaining row claims and clearing the history takes them all, and the lookup then reads the row by its mapping while that names a live entry, else by the title match the home page stored for it. A row that never recorded an id goes by its mapping alone, as before. The fallback takes the stored `(show key → kitsu_id)` mapping first. A mapping is dropped only when it is a music entry; one its count or cour doubts is passed over, and one only the provider's title doubts — the provider lists Seitokai ni mo Ana wa Aru! as "There Is Also a Hole in the Student Organization!", which shares only "student" with Kitsu's English title for it, "Even the Student Council Has Its Holes!" — is kept when a play stored it, known by the mark a play leaves beside the mapping it stores, naming the entry — any other write of the mapping, dropping it and removing the show take the mark — and passed over when a resolve guessed it; a mapping stored before plays left the mark got one once, at upgrade, when it was written within seconds after the show's watch stamp — the rule earlier versions read it by — and reads as a guess otherwise; the marking changes nothing an earlier version reads, so a downgrade opens the cache as before and ignores the marks. Past the mapping, the fallback searches Kitsu by the row's title, or by the words of the show key's slug (`there-is-also-a-hole-in-the-student-organization-10497`), and never takes a hit whose titles share too few words with the row's — under a third of either side's words, with neither title's words all in the other, and the hit not a single long word leading the row's title: Kitsu answers words it does not carry with its closest entry, Here is Greenwood for those, which shares only "is" with them. Both sides apply one rule over the shared vectors in `tests/fixtures/title-words/`, with sequel markers — season, part, cour, ordinals, numbers, roman numerals — not counted as shared words. A guess from the slug's words is stored as the mapping only while the row is still in history — a row removed while its resolution was out leaves nothing to map, and the title match the resolution would have stored is dropped the same way — and unless a play's mapping already stands, whatever doubted it: a play's mapping a read passes over on its count or cour stays until the next play of the show replaces it or it expires. A row nothing matches renders as a card with the history title, its first two characters in place of a poster, that opens a search for its title. When two providers have each left a row for the same show — a row from anidb.app's days and hianime's beside it — the detail page and the strip pick the same row. A watch writes its moment beside its history row and in the cache, and a row ranks by the later of the two, so a cache that refused the stamp still leaves the row ranked as the watch it was; the latest moment wins, a row with one beats a row without, and when the moments do not separate two rows the further progress does, counted in Kitsu's numbering, since two providers' rows can count from different offsets.

## Streaming listings that are not the show's

AniList's `streamingEpisodes` is a Crunchyroll listing, and AniList attaches the same listing to the wrong entries often enough to matter. Every Gintama TV entry with a listing carries one and the same 49 entries — the 2006 series' first 49 episodes — so Gintama. (2017, 12 episodes) would show 2006 stills for all twelve. Sequels carry their first season's listing, split cours carry the whole season, and a franchise numbered continuously across seasons puts one season's listing (My Hero Academia 139–159) on several entries.

The backfill fills stills by episode number, so before it fills any it asks whether the listing describes the show, against the Kitsu page it is filling:

1. **The titles decide when there are enough of them.** Kitsu's title and the listing's (with the `Episode N -` prefix removed) are compared for every page episode both title. With at least three such pairs, the listing fits when at least half agree. Two titles agree when the letters and digits of one contain the other's, case and punctuation aside and a number spelled out from zero to twenty read as its digits — which also keeps it out of the distinctive words, being under three characters — ("That Day" and "That Day - The Fall of Zhiganshina (2)", "Karen Bee, Part One" and "Karen Bee, Part 1"), the contained one at least three characters long and any number it starts or ends with meeting a whole number, as the longer title's own words split it ("Part 1" is not inside "Part 11", while "Chapter 1" is inside "Chapter 1 - 100 Years Later"), and full-width letters and digits read as ASCII, or when they share a distinctive word: three or more characters, not a stop word (*the*, *and*, *for*, *from*, *with*, *part*, *episode*), and carried by no more than a quarter of the compared pairs, or by only one pair when fewer than eight are compared. A word that recurs through the show's titles — "Kaguya Wants to …" — says nothing about which episode a title names. A placeholder on either side — no words, or `Episode` and a number such as `Episode 5` or `Episode 5.5` — is not compared. Correctly matched listings agree on 75–100% of the pairs in the table below, mismatched ones on 15% at most, so the halfway line falls in a wide gap, and a minority of titles worded differently never refuses a listing.
2. **Otherwise the shape decides.** With fewer than three pairs — Kitsu has no titles, or the listing and the page barely overlap — a finished show with a known episode count refuses a listing numbered past that count. A show still airing, or one AniList has no count for, keeps its listing.

A refused listing fills nothing: the page shows Kitsu's stills where Kitsu has them and placeholders elsewhere, as for a show AniList has no listing for. The cached listing is kept whole (`anilist:eps-thumbs:v2:k<kitsu id>`, a day), and the rule runs on every page it fills, so the verdict follows the page's titles rather than the cache. The key moved from `v1` when the row began to carry titles; a `v1` row, which held a number-to-still map, is never read again.

A listing numbered continuously across seasons is refused rather than re-based by the season's first number, because its shape does not say whose it is. The same 139–159 listing sits on My Hero Academia's first four seasons as well as its seventh; Shangri-La Frontier's first and second seasons both carry 26–50, and Kusuriya no Hitorigoto's first season carries 25–48 — a season the length of the entry's own, numbered on from it, belongs to the entry in one case and to its sequel in the other. Only Kitsu's titles could confirm an offset. Where Kitsu titles the season, it has had every still too (My Hero Academia 7, Solo Leveling season 2); where it does not (Rurouni Kenshin: Kyoto Douran, MF Ghost season 2, Kamonohashi Ron season 2, Shinigami Bocchan season 3), nothing could confirm one. Those seasons' episodes keep their placeholders — as they did before the rule, since a listing numbered from 25 never matched a Kitsu episode 1.

## Failure modes the bridge tolerates

- **Kitsu has no MAL mapping** — aniskip lookup returns an empty list (the player just doesn't show the skip button). The banner and episode-thumbnail backfills use the AniList mapping instead when there is one; with neither mapping, the banner falls through to the blurred-poster placeholder and episodes keep their placeholder stills.
- **The provider is unreachable** — with the one provider that ships, the walk ends on the unreachable verdict and persists nothing. Where several are configured, the walk runs against the next provider. A clean catalogue miss reached there — every search completed and nothing matched; an episode dead end on a show that was found persists nothing — is persisted as that provider's negative verdict, naming it, as is the availability probe's answer that the show is listed without the requested mode — unless a live positive row remembers the unreachable provider, in which case the miss is not the verdict at all — the caller sees that provider's unavailability, and nothing persists, since the row's own provider has not denied the show and an unrelated absence must not overwrite its evidence — and a persisted one is served only while that provider's gate has been seen answering since it last failed and the primary's gate is refusing — a breaker open for its cooldown, or a rate-limit pause running for its advertised window; both end on the clock, with nothing having to prove the primary is back, and at the window's end the row stops standing and the probe runs again.
- **The provider has no candidate matching any title** — the play path returns `NoResults`; the frontend renders an "isn't in the streaming catalogue" overlay instead of a cryptic backend error. A provider that answered conclusively ends the walk — the miss is not retried on the next provider — unless a positive availability record put that provider first, in which case its miss is set aside and the rest of the order is asked, the record proving the show and not every episode. A provider whose answer settles nothing — the show found, every sampled episode row silent about the requested mode — does not end it; the walk moves on.
- **The picker can't disambiguate** — with a count, the closest count within tolerance and its tie-breaks; without one, the countless order above, among the hits the title searched, their own year or the entry's name vouches for. This is the worst case for correctness, but it's still a real entry on the provider; the user sees a sub-show rather than no show. They can pick the right one manually from search.
- **A cached play-resolution URL stops working** — the silent retry path evicts the cached row and re-resolves once before surfacing an error to the user.

## Show keys

Every store a resolve stamps holds the show key the resolve produced, as a string: history rows, the numbering sidecar beside the history file, the watched-at stamps and the reverse mapping key on it, and the resolution-cache row — keyed on the request itself — carries it in its value. A provider's key carries its label as a prefix (`hianime:cowboy-bebop-1281`). The read side parses the string back: a known label names its provider; anything else is a bare id that names no provider — anidb.app's slugs (`one-piece-69`), which every row its resolves wrote holds, and the allanime-era ids that predate slugs. Nothing migrates: a bare row keeps resolving to Kitsu by its recorded id, its mapping or its slug's words. The renderer treats the id as opaque except for that label, which it reads to say which provider's title a title-match cache key is for: the title-match cache is keyed per provider — and a bare row's under a `legacy` segment of its own — so two providers naming different shows identically cannot read or overwrite each other's mapping.

The cross-cour guard on the reverse mapping write compares the provider's title against Kitsu's slug convention, and it guards every provider's ids: the resolve carries no identity the guard could defer to — no Kitsu or MyAnimeList id, only the title, year and count the picker scored — so a wrongly picked sibling cour on any provider would otherwise persist the caller's Kitsu id under its slug, the row Continue Watching and resume then read. Lifting the guard for a provider wants identity provenance the resolve does not carry yet.
